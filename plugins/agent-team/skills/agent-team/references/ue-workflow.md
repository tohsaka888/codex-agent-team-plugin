# UE Agent：UI/UX 基线

适用：App、网页及其他界面需求的新设计或实质视觉/交互修改。沿用已确认图的小修改核对版本和范围即可；非 UI 任务无需视觉评审。

## 职责与输入

UE 是团队预设职责，由 Codex 原生工具按需派生，不是保证宿主具有的内置 agent_type。委派明确职责 UE、目标、平台、关键流程、既有图/规范、写入范围、验收及产物。工具不支持 UE 类型时选实际支持的类型并明确职责，不伪造原生角色。

协调者先恢复已有产品决定，再询问用户是否有 UI 图、品牌/布局要求或现有设计。已有图可以是参考素材；未明确确认具体版本时不能直接作为实施基线。有匹配范围的已确认设计时复用并记录依据。

## 无图时生成候选

核验实际执行环境的 imagegen 技能与生图工具，读取真实 SKILL.md 后调用工具生成候选。SSH 文件访问不等于远程子 Agent 有生图能力；同一授权任务中有能力的执行者可以生成并交接实际图文件。能力不可用时明确阻塞并请求素材或能力补齐，不把文字描述当成已生成的图。

候选覆盖关键页面及适用的正常、加载、空、错误状态；提供页面/状态清单与 UX 说明，包括操作、跳转、反馈、响应式和无障碍约束。图无法表达的交互写入说明；静态图不证明交互可用。

向用户展示可查看的图、版本和确认范围，等待明确确认。意见形成新版，记录差异并重新评审受影响范围。部分确认只放行对应页面和状态；用户沉默、超时及 Agent Review 不代替人工确认。

## 确认后归档与规范

归档到目标项目 `docs/ue/<feature>/<version>/`：

- 原图/生成图，注明来源与页面/状态；生成图保存提示词，不存凭据或无关私人信息。
- `ux.md`：关键流程、反馈、状态、响应式与无障碍要求。
- `review.md`：确认对象、版本、文件 SHA256、用户原话、会话、时间和范围。缺失证据保持未知。

用户确认 UI 后才生成项目 `design.md`，采用 [Google 格式规范](https://github.com/google-labs-code/design.md/blob/main/docs/spec.md)的 tokens 与说明；实施时读取实际规范和目标项目工具版本。沿用现有规范路径，不创建仅大小写不同的第二个文件。

颜色、字体、间距、形状和组件规则反映已确认图；关键选择无法从图确定时提出具体核对，不自行扩展视觉方向。正式工作前按 [环境预检](preflight.md#补齐-designmd-cli)核验并补齐官方 `@google/design.md` CLI；规范形成后用项目本地 `designmd lint <实际规范路径>` 或已有脚本校验，记录版本、命令、退出码及错误/警告处理依据。工具缺失或 lint 有错误时保持规范校验未通过，不以人工 front matter 核对替代；lint 不替代视觉评审。实质变化保留旧版并重新确认。

## 开发依赖与审查

规格及工单可先形成并确认，UI 工单明确依赖对应图已确认、归档及规范校验完成。依赖未满足时不分派对应 UI 实施；独立且已批准的后端任务按真实依赖推进。to-spec、to-tickets 的正文读取、产物形成和用户确认分别保留证据。

开发合同必须引用确认图、ux.md、design.md 和确认依据。审查者读取相同版本，对比真实实现截图、用户流程和适用状态；交付截图独立保存，不覆盖确认图。用户视觉确认、Agent Review 和最终交付验收分别记录。

已有 UI 用当前截图进入补充评审，再安排差异工单；不追认历史确认，不擅自干预其他运行会话。UE 的真实 UUID、职责、目标、活动、实际使用 Skills 和文件通过既有 task-report 回报；只读看板不批准设计或控制执行。
