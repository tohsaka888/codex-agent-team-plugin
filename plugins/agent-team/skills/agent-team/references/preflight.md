# Agent Team 环境检查与补齐

这是主 Agent 执行的工作流检查，不是自动检测程序、权限系统或 UI 审批。检查实际执行环境；本机文件存在不能证明 SSH 主机或另一工作区可用。不要运行未知安装脚本、输出凭据或修改全局登录。

## 检查清单

| 项目 | 核验与通过依据 | 缺失时处理 |
| --- | --- | --- |
| 宿主原生团队能力（必需） | 当前会话实际提供派生、补充任务、收集结果和等待的原生工具；Codex及其他客户端分别按真实接口核对，不能用进程名判断能力或独立执行器替代 | 说明缺少哪些工具，要求在支持原生团队的宿主会话继续；不制造无意义子 Agent 来探测 |
| 工作区与授权（必需） | 实际主机、cwd、目标目录可读；读取适用 AGENTS.md 和项目规则；核对现有用户改动及本次范围。写入任务另核对目标路径写权限 | 明确缺失路径或权限；保留用户改动，不通过修改权限或登录绕过限制 |
| Matt Skills（必需，按任务） | 标准新功能核对 to-spec、to-tickets、implement-spec、tdd、code-review；诊断/架构/领域任务另核对 diagnosing-bugs、codebase-design、domain-modeling 等实际所需技能。核对当前会话技能元数据、实际 SKILL.md、必要引用及脚本依赖 | 分别列出未安装、不可发现、不可读取或依赖缺失；按下述方式补齐，不把“任意可用 Skills”当作 Matt |
| 项目流程上下文（必需） | 核对工单保存/关闭方式、分类词汇、领域上下文及现有规格/确认记录；优先使用项目已有文件。没有外部 tracker 时，明确采用本地 Markdown 的保存位置、依赖表达和完成记录 | 准备本地适配说明；按 setup-matt-pocock-skills 的适用流程配置。其他项目不要求存在本仓库同名文档，但须有等价上下文 |
| 实现及验证工具（按任务必需） | 从项目实际配置确定运行时、包管理器、构建、测试及审查命令；读取版本/运行无副作用的检查；只有适用技能真正依赖的 Bash、CLI、服务等才是必需 | 列出缺失命令和所影响阶段；不能报告不存在的测试通过，不为文档任务强制安装全部开发工具 |
| design.md CLI（UI 任务必需） | 涉及生成、修改或校验设计规范时，在实际执行主机核对官方 `@google/design.md` 的安装路径、版本、Node/npm 兼容性及 `designmd` 可运行；已有规范运行实际 lint 并保存输出，尚无规范时先核验帮助，确认图后再校验文件 | 按下述官方来源和项目级方式补齐；缺失、无法运行或 lint 有错误时，相关规范校验及依赖它的 UI 实施暂缓。非 UI 且不涉及规范的任务标为不适用；人工核对不替代 CLI 通过 |
| Git 与写入隔离（按执行方式必需） | 核对 Git 状态、可解析基线及已有工作树。并行写入必须独立 worktree/分支/范围，串行集成；共享工作区仅一个写入者。完整上游 code-review 需要固定且非空的差异 | 无基线或 worktree 条件时明确限制；采用已授权的单写入者/限定文件审查适配，不能冒称完整上游执行；不擅自提交、清理或重置 |
| 只读看板（展示项） | 核对插件工具能调用、看板资源能读、当前真实会话可绑定；Node/MCP 运行条件以实际安装配置为准，不能只看 PATH。任务回报/Hook 另核对真实接入 | 展示故障如实说明，可继续已满足执行条件的工作；不得把空态、缺失回报或未知状态解释为团队完成 |

技能检查区分安装、发现、读取、执行：先核验元数据和文件可读性，到了实际阶段再读取完整正文与必要引用；子 Agent 接到任务后核验自己的可用技能并回报实际使用情况。无需预加载31个技能；未选用的技能标为不适用并说明任务依据。只找到磁盘文件但当前会话未发现时，不标通过。

非 Codex 可通过显式指令读取 SKILL.md；客户端没有原生隐式发现时记录为“显式读取”，不冒称隐式加载。同步脚本仅需 Node 内置模块，独立 Web 指向明确 workspace/data-dir；Codex 注册表、MCP 和 Hooks 均不是独立模式必需项。缺少生命周期观察时展示同步覆盖限制，不让 Hooks 缺失阻断业务追踪。

## 补齐 Matt Skills

上游来源为 mattpocock/skills；本仓库已核验版本为 d81f3a183412e71a5b1e84ca21bc1a35eea03a60（MIT）。复用该版本时携带许可证和附属资源，记录来源、版本、安装范围；其他版本须核对其实际内容，不能冒称已验证。

优先通过宿主提供的 skill-installer 安装缺失技能到目标项目 .agents/skills/，先读取安装技能的 SKILL.md；按实际固定来源路径安装，不猜测目录、不覆盖已有用户技能。检查所选技能引用的额外技能和工具，递归补齐本次适用依赖。没有安装技能时提供具体缺失清单与固定来源，请用户选择可用安装方式，不默默改成普通协作。

安装是可审查的准备工作，受当前用户授权及权限约束；不能以启用团队为依据修改全局配置、登录或发布。必要时在补齐后使用新会话让宿主发现技能，再核对元数据；不能保证热加载。保留上游 disable-model-invocation 标记；安装、读取和团队授权不等于调用了所有用户专属技能。当前阶段需要主动调用时，说明具体技能并取得对应调用授权，不重复索取已有明确授权。

## 补齐 design.md CLI

官方来源为 [google-labs-code/design.md](https://github.com/google-labs-code/design.md)，npm 包为 `@google/design.md`；[格式规范](https://github.com/google-labs-code/design.md/blob/main/docs/spec.md)与工具版本分别记录。先检查目标项目的 package.json、锁文件和实际安装目录，复用已有固定版本及项目脚本；不能只凭全局 PATH 或本机安装推断 SSH 环境就绪。

本仓库已固定 `@google/design.md@0.4.0`，从仓库根目录执行：

```powershell
npm ci
npm ls "@google/design.md" --depth=0
./node_modules/.bin/designmd --help
npm run design:lint
```

依赖已安装且可用时跳过 `npm ci`。其他目标项目先核验官方包、所选固定版本及运行时要求，在当前授权范围内用 `npm install --save-dev --save-exact "@google/design.md@<已核验版本>"` 安装到该项目；命令中的版本占位符必须替换为实际版本，不直接照抄，不擅自升级已有依赖。使用项目本地 `designmd lint <实际规范路径>` 或已有 lint 脚本；Windows 使用不带点的 `designmd` 别名，避免 `.md` 文件关联干扰命令解析。无 Node 项目使用明确的项目工具目录，记录路径及版本，不默认全局安装或临时下载最新版。

安装失败时记录实际错误及受影响阶段，核对 registry/代理配置但不擅自改全局配置或登录，不尝试名称相似的未知 CLI。允许继续收集图和只读探索；设计规范存在后必须执行 lint。记录命令、版本、文件路径、退出码、错误和警告处理依据；有错误不能标通过，警告逐项评估。人工核对 front matter、章节及确认图的一致性作为补充，CLI 通过也不代替视觉评审。
