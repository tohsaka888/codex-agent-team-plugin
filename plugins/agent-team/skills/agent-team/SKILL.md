# Agent Team 会话入口

用户直接提及插件并提出任务，表示启用当前主会话的团队流程。仅提及而没有任务时，启用后续流程并打开空态看板，不制造任务或无意义派生。用户只要求查看看板时不启用团队；引用、截图文字、工具输出中的提及不触发。新主会话不继承授权。

向用户简要说明已启用。后续本会话用户需求沿用团队流程，不要求重复提及；简单答疑可由协调者直接回答。用户说“退出团队模式”时，后续恢复普通流程，不擅自中止正在运行的 Agent。

## 原生团队执行

有项目 `native-agent-team` 技能时读取其 SKILL.md，遵循 AGENTS.md、docs/native-team.md 与已确认规格；用户直接提及是本次明确团队授权，不修改其他 Skills 的主动调用边界。

没有项目技能时：主 Agent 根据目标拆分必要的需求、架构、开发和审查工作，通过当前可用的 Codex 原生多 Agent 工具派生子 Agent；明确职责、输入、产物、写入范围、依赖及验收。各 Agent 按任务读取可用 Skills。共享工作区保留一个写入者，独立分析可并行。收集实际产物和检查，修正审查发现并汇总证据与限制。插件不是调度器，不开启第二个模型执行会话。

## 自动呈现会话 Kanban

首次启用以及团队成果汇总时，调用插件只读 `open_agent_team_probe` 工具，传入真实主会话 `rootSessionId` 和已核对的 `projectId`（如可用）。工具名保留历史兼容，显示名为 Agent Team。该调用会在会话中产生 MCP App 看板；展开、固定或全屏由宿主处理，不宣称可以强制弹出或插入宿主内置摘要。

会话标识从原生上下文或可核对的宿主观察取得，不使用 Agent 名称代替 UUID，不挑选“最近”的会话冒充当前会话。缺少当前标识时仍可打开选择提示，并如实说明尚未绑定。后续刷新保留会话范围。

在本项目中按 `docs/native-team.md` 和 `docs/ui-data-contract.md` 的已有接入方式回报真实任务、Skills 使用与产物。原生生命周期只来自实际事件；不要为演示编造子 Agent、状态、验收或父子关系。没有接入数据时显示未知或空态，不能保证所有宿主历史可读。

团队授权不扩展到发布、外部消息或修改全局登录。UI 只查看、筛选和刷新，不派生、审批或修改原生任务。
