# UI Check：产品实际界面与确认设计一致性

适用：Web、App 及其他产品界面的新实现、视觉/交互修改和 UI 缺陷修复。Reviewer 在交付审查和修正复查时执行；Coordinator 在工单及委派合同中列明覆盖范围。纯后端、无界面变化的任务记录不适用依据。

## 输入与验收条件

UI 工单及负责 UI 实现/审查的执行卡必须登记 Agent `check` 类型的 UI Check AC。明确页面、状态、设备/视口和核对方法；父卡与执行卡分别提交证据。编码任务仍需独立的 `unit_test` AC。UI Check 使用现有验收字段，不新增自动图像判定能力。

开始前核对以下输入及对应版本：

- 用户确认的 UI 图、确认范围和文件指纹；参考图与已确认实施图分别标明。
- 同一基线的 `design.md`、`ux.md`，以及已明确允许的差异。
- 当前产品的启动/访问入口、构建或代码版本、测试数据、目标页面/状态、设备/视口、主题。

基线图与规范冲突时列明冲突并由协调者恢复决定；不能只选规范文本忽略确认图。必要基线或实际运行能力缺失时，对应 AC 保持 pending/unknown 并报告缺项。

## 执行步骤

协调者在实施前形成下述覆盖矩阵并提供给实现者；Reviewer 复用并核对当前范围，而非等到交付才重新盘点页面。切片完成时关联对应截图和操作证据，综合复核集中检查跨切片风险及缺口；版本变化仍按验收合同重新核对受影响项。

1. 建立覆盖矩阵：每行指定一个页面、状态、设备/视口、主题及对应确认图。覆盖本次受影响的正常、加载、空、错误和关键交互状态；响应式、深浅主题、键盘/无障碍按已确认范围列入。未适用项注明依据，不以单张首页截图代表全产品。
2. 运行当前产品，按矩阵操作并采集真实效果图。Web 使用实际浏览器页面；App 使用实际设备或模拟器中的运行界面。记录平台、浏览器/系统版本、视口或分辨率、缩放/字体倍率、主题、数据、进入步骤、采集时间和产品版本。设计稿、生成的效果图、未运行的 HTML 或旧版本截图不能作为当前产品截图。
3. 使用可用的图像查看工具实际打开确认 UI 图和产品截图，逐对进行视觉比对，同时读取 design.md 和 ux.md。尽可能使用匹配的视口、主题、数据和状态；无法匹配时注明原因与可核对范围，未覆盖部分保持待核对。
4. 核对下表各维度；实际操作验证交互。每个矩阵条目输出通过、需修正或未核对，并关联两张图和具体依据。截图不能证明跳转、反馈或键盘行为可用。
5. 保存 UI Check 报告和真实截图，关联当前 task/run 的产物及结果。Reviewer 在逐项 AC evidence 中引用报告、图片对、当前版本和结论；全部必需条目核对通过、差异已修正或有明确允许依据后，该项才能 passed。

| 维度 | 核对内容 |
| --- | --- |
| 布局与层级 | 区块位置、宽高比例、对齐、留白、间距、滚动区域及信息层级 |
| 样式与组件 | 颜色、字体/字号/字重、圆角、边框、阴影、图标和图片、组件尺寸与状态 |
| 内容与可读性 | 文案、数据呈现、换行、截断、遮挡、溢出、对比度及控件可辨识性 |
| 状态与适配 | 正常/加载/空/错误/选中/禁用等适用状态，响应式、主题、安全区及软键盘影响 |
| 交互与 UX | 入口、点击/输入、跳转、返回、反馈、焦点、键盘与适用无障碍行为 |

人工图像比对是基础要求；可用叠图或像素差异工具辅助定位，但仅报告实际执行的工具与结果。字体抗锯齿、动态数据等差异说明影响，不自行设置相似度阈值或仅凭差异分数通过。项目已有明确阈值时按该约定执行。

## 证据、退回与复查

建议在 `docs/ue/<feature>/ui-check/<result-version>/` 保存 `ui-check.md` 和实际截图；沿用项目已有证据目录也可。确认图保持原位置，交付截图不覆盖基线图。

报告必须包含：task-id/run-id、结果版本、基线版本及图/规范引用与指纹、运行环境、覆盖矩阵、每对设计图/实际图的结论、交互操作结果、差异清单和未核对范围。差异写明页面/状态/区域、期望与实际、严重度、图片依据和修正建议。没有差异也列出实际核对过的图片对。

有影响已确认要求的差异时，UI Check 标 failed，Reviewer 退回并由协调者安排返工；证据缺失或工具不可用时保持 pending/unknown，不声称完成视觉验收。修正后重新运行并采集当前截图，复查原差异及受影响状态，保存新结果版本与审查记录。版本/产物变化后按验收合同重新绑定证据，保留历史。

用户设计确认、Agent UI Check、独立 Agent Review 和适用人工交付核验分别记录。UI Check 通过不能代替用户对新设计方向或人工核验项的确认；design.md lint、单元测试、构建及代码审查通过也不能代替 UI Check。
