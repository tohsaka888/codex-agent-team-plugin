# 0001：独立 Web 与通用交互追踪

状态：accepted（2026-10-09）。依据：用户对[评审 v1](../../.scratch/web-decoupling/review-v1.md)回复“确认”；具体版本与 SHA256 见[决定记录](../../.scratch/web-decoupling/decision-v1.md)。时间线具体视觉另行确认。

## 问题

默认入口打开 Codex 内嵌看板，HTTP 与前端仍加载 MCP 依赖，通用 activity 只有摘要。用户要求展示追踪完全独立于 Codex，在网页查看分派、消息、回复、状态和协作时间线；执行继续由宿主负责。

## 决定

通用事件核心通过本地归档接收明确回报；独立 HTTP 服务与浏览器包仅需 Node，不读取 Codex home/SQLite，也不依赖 MCP。可移植启动器核对工作区、数据目录与已登记服务实例，返回团队 URL 并打开系统浏览器。独立资源随 Skills 安装，MCP/宿主观察保留为可选兼容适配器。

交互记录使用稳定消息标识、team/task/run关联、发送接收者、正文、回复关联、来源及时间。HTTP 使用归档 sequence 游标；timestamp是生产者声明的事件/观察时间，recordedAt是归档时间，不认证真实原生发生时间。缺失关联为未知，未采集历史不补造。状态消息不改变任务、执行、评审或验收。

## 备选与影响

仅换成HTTP地址仍保留依赖耦合且缺少消息模型；全面重写会丢失已有投影/边界验证。本决策复用现有视图和事件归档，拆开服务与桥接边界。

默认入口改变，旧MCP能力保留；服务默认仅本机访问，没有独立执行器、模型调度、网页任务控制、认证系统或跨主机写入服务。本机实例核对防止误复用，不构成针对同用户恶意进程的认证边界。
