# 人工核验细化 v2

2026-10-04。依据用户明确反馈：“如果不需要人工核验就不需要这个checklist，人工核验必须要具体到验收什么功能，怎么验收”。本次有界修正覆盖 v1 的“每卡必须人工 delivery”约定，其余非空 AC、单元测试、UE 原型确认、版本和证据隔离继续适用；v1 评审原文不改写。

每卡仍有至少一项具体 Agent 验证 AC。仅需人工核验的功能、体验或设计决定添加 human 项；内部分析、独立审查、自动测试足以完整核验的执行不附加通用用户确认项。实际需要人工验收时不得通过删除项绕过；分派前由协调者依据业务需求明确适用范围。

人工项必填 manualCheck.entry、manualCheck.steps（非空步骤数组）、manualCheck.expected，分别表达入口、操作步骤、可观察预期结果，label 描述具体验收功能，method 说明核验方式。不得使用“用户验收本卡结果”“完成开发”“正常”作为验收内容；结构校验不能替代协调者和 Reviewer 对具体内容的审查。

例：label=登录成功后进入首页；入口=测试版 App 登录页面；步骤=启动 App→输入测试账号与密码→点击登录；预期=进入首页并显示该账号昵称，无错误提示。UE 项列明打开哪份原型、核对哪些页面/状态以及应满足的设计要求。

无需人工项显示“无需人工核验”，不伪造“人工已验收”；全部 Agent 条件和当前独立审查满足即可完成。有人工项时仍必须取得匹配当前对象、版本、指纹和范围的真实用户决定。修改人工核验入口、步骤或预期结果也改变 AC 指纹，旧验证/认可失效。

验证边界沿用已确认的公开 CLI→快照→详情 DOM；新增覆盖无需人工完成路径、缺人工步骤拒绝、具体步骤详情可见和无需人工详情提示。
